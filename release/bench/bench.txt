  A kernel's tail padding is EXCLUDED, on both vendors: gfx10+ pads with
  s_code_end, CDNA3 with s_nop, and NVIDIA with NOPs to a 128-byte
  boundary. Counting it reads gfx1100's vadd as 146 instructions rather
  than 32, and sm_70's vadd as 24 rather than 17. Only a TRAILING run is
  dropped; a NOP inside the body is a real scheduling slot.

  NV SASS is sm_70 via ptxas -O3 (tools/fetch-ptxas.sh). Every kernel
  measures 128.0 bits per instruction EXACTLY -- the figure §6 of the ISA
  document carried as a citation for four revisions is now measured, and
  it holds from Volta through Blackwell. Pre-Volta is excluded: it uses a
  64-bit encoding with separate control words that a 16-byte walk would
  silently miscount.

  CCV dynamic is MEASURED on the simulator: lane-instructions divided by
  threads, which for a fully-active warp is the issue count. AMDGCN has no
  simulator here, so its dynamic column is filled in only where the kernel
  provably has no loop and static and dynamic must therefore agree. The two
  reduction kernels loop on both sides and are left blank rather than
  modelled.

  SIMT is CCV ONLY and is not comparable as printed: a CCV warp is 32 lanes
  (§1) and a gfx900 wavefront is 64, so the same 32-thread block that fills
  a CCV warp half-fills theirs. Comparing occupancy needs the same block
  size expressed in each machine's own warp width, which these kernels do
  not hold fixed.

  LANE-ACT is the energy number (O-33), and it is the ONLY column that
  moves in the right direction when lane-0 masking fires: masking adds a
  broadcast instruction and removes 31 lane-activations, so an instruction
  count alone reports the cost and hides the win. `of issued` is
  lane-activations over lane-instructions -- the share of issued lane slots
  that actually did work. It has no AMDGCN counterpart here: gfx900 gates
  on an exec mask this project does not model, so there is nothing honest
  to put in a comparison column.

  PTX is a VIRTUAL ISA. Task complexity, NOT density -- ptxas expands,
  schedules and re-allocates it before anything executes.
