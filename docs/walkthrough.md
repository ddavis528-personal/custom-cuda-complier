# Walkthrough — one kernel, source to execution

A complete trace of the pipeline for a kernel that works today. Every listing is
generated by `tools/make-walkthrough.sh`; nothing here is transcribed.

```
vadd.cu → clang → NVVM IR → CCGLowerKernelArgs → ccg-llc → ELF
        → .text → ccg-sim
```

---

## 1. The kernel

```cuda
// Same kernel, with the alignment the runtime can vouch for declared per
// argument (O-23). clang's align_value lowers to LLVM's align parameter
// attribute; the backend queries alignment, not the attribute.
#define __global__ __attribute__((global))
#define ALIGNED __attribute__((align_value(65536)))
#include <__clang_cuda_builtin_vars.h>

__global__ void vadd(float *ALIGNED c, const float *ALIGNED a,
                     const float *ALIGNED b, int n) {
    int i = blockIdx.x * blockDim.x + threadIdx.x;
    if (i < n) c[i] = a[i] + b[i];
}
```

`align_value(65536)` is O-23's per-argument alignment attribute — the only
target-specific thing in this source. It is not optional today: codegen does not
yet implement the unaligned shape, which needs four addends against a
three-input AGU, and rejects it with a diagnostic (F-27).

## 2. clang, unmodified

No CUDA toolkit is installed. `-nocudainc -nocudalib` skip the SDK and
libdevice; `threadIdx` and friends come from clang's own
`__clang_cuda_builtin_vars.h`.

```llvm
define dso_local void @_Z4vaddPfPKfS1_i(ptr nocapture noundef writeonly align 65536 %0, ptr nocapture noundef readonly align 65536 %1, ptr nocapture noundef readonly align 65536 %2, i32 noundef %3) local_unnamed_addr #0 {
  %5 = tail call noundef i32 @llvm.nvvm.read.ptx.sreg.ctaid.x()
  %6 = tail call noundef i32 @llvm.nvvm.read.ptx.sreg.ntid.x()
  %7 = mul i32 %5, %6
  %8 = tail call noundef i32 @llvm.nvvm.read.ptx.sreg.tid.x()
  %9 = add i32 %7, %8
  %10 = icmp slt i32 %9, %3
  br i1 %10, label %11, label %19

11:                                               ; preds = %4
  %12 = sext i32 %9 to i64
  %13 = getelementptr inbounds float, ptr %0, i64 %12
  %14 = getelementptr inbounds float, ptr %2, i64 %12
  %15 = getelementptr inbounds float, ptr %1, i64 %12
  %16 = load float, ptr %15, align 4, !tbaa !5
  %17 = load float, ptr %14, align 4, !tbaa !5
  %18 = fadd contract float %16, %17
  store float %18, ptr %13, align 4, !tbaa !5
  br label %19

19:                                               ; preds = %11, %4
  ret void
}
```

Three things the backend is built around: the
`llvm.nvvm.read.ptx.sreg.{tid,ctaid,ntid}.x` intrinsics, which ISA §5.3 divides
between the launch block and `srd`; `getelementptr inbounds`, the guarantee that
makes the windowed address model work; and the `!nvvm.annotations … "kernel"`
marker, which is how the ABI pass finds kernels without the frontend being
modified.

## 3. Kernel ABI lowering

```llvm
define dso_local void @_Z4vaddPfPKfS1_i() local_unnamed_addr #0 {
  %ntid = load i32, ptr addrspace(4) inttoptr (i64 131072 to ptr addrspace(4)), align 4, !invariant.load !5
  %.val = load i32, ptr addrspace(4) inttoptr (i64 131128 to ptr addrspace(4)), align 4, !invariant.load !5
  %1 = tail call noundef i32 @llvm.nvvm.read.ptx.sreg.ctaid.x()
  %2 = mul i32 %1, %ntid
  %3 = tail call noundef i32 @llvm.nvvm.read.ptx.sreg.tid.x()
  %4 = add i32 %2, %3
  %5 = icmp slt i32 %4, %.val
  br i1 %5, label %6, label %17

6:                                                ; preds = %0
  %.rbase4 = load i32, ptr addrspace(4) inttoptr (i64 131120 to ptr addrspace(4)), align 4, !invariant.load !5
  %7 = zext i32 %.rbase4 to i64
  %.window5 = shl nuw nsw i64 %7, 16
  %.ptr6 = inttoptr i64 %.window5 to ptr
  %.rbase1 = load i32, ptr addrspace(4) inttoptr (i64 131112 to ptr addrspace(4)), align 4, !invariant.load !5
  %8 = zext i32 %.rbase1 to i64
  %.window2 = shl nuw nsw i64 %8, 16
  %.ptr3 = inttoptr i64 %.window2 to ptr
  %.rbase = load i32, ptr addrspace(4) inttoptr (i64 131104 to ptr addrspace(4)), align 4, !invariant.load !5
  %9 = zext i32 %.rbase to i64
  %.window = shl nuw nsw i64 %9, 16
  %.ptr = inttoptr i64 %.window to ptr
  %10 = sext i32 %4 to i64
  %11 = getelementptr inbounds float, ptr %.ptr, i64 %10
  %12 = getelementptr inbounds float, ptr %.ptr6, i64 %10
  %13 = getelementptr inbounds float, ptr %.ptr3, i64 %10
  %14 = load float, ptr %13, align 4, !tbaa !6
  %15 = load float, ptr %12, align 4, !tbaa !6
  %16 = fadd contract float %14, %15
  store float %16, ptr %11, align 4, !tbaa !6
  br label %17

17:                                               ; preds = %6, %0
  ret void
}
```

The kernel now takes **no parameters at all** — they arrive in the launch block
(§5.2), so the signature says so.

And the payoff of doing this in IR rather than the backend: each pointer is
`(zext rbase << 16)` with **no `add`**. The in-window offset was a constant zero
because the argument is aligned, so the optimiser folded it away. O-23's
one-register form arrives from `instcombine`, not from a backend special case.

## 4. Native assembly

```
_Z4vaddPfPKfS1_i:
	movi r0, 2
	ld.global r1, [r0 + 0]
	srd r2, 0
	srd r3, 1
	mad.lo r1, r3, r1, r2
	ld.global r2, [r0 + 56]
	setp.le p0, r2, r1
	@p0 bra LBB0_2
	ld.global r2, [r0 + 48]
	ld.global r2, [r2, r1, 1, 0]
	ld.global r3, [r0 + 40]
	ld.global r3, [r3, r1, 1, 0]
	fadd r3, r2
	ld.global r0, [r0 + 32]
	st.global r3, [r0, r1, 1, 0]
LBB0_2:
	exit
Lfunc_end0:
```

| | |
|---|---|
| `f48 r0, 2` | Format F's 48-bit form materialises the launch window in one instruction |
| `ld.global r1, [r0 + 0]` | `blockDim.x` — launch-*time* data, so the block supplies it (§5.3) |
| `srd r2, 0` / `srd r3, 1` | thread and CTA identity — the only values no memory location can supply |
| `mad.lo r1, r3, r1, r2` | the three-source form takes `ctaid*ntid + tid` in one instruction |
| `por p0, 4, 0` | O-24: Formats C/C′ carry a *mandatory* qualifier and there is no unpredicated compare, so a kernel must manufacture a true predicate. Compressed forms are never predicated, which breaks the cycle |
| `@p0 setp.le p0, r2, r1` | self-guarding — guard and destination are the same predicate, so the effective file stays at four |
| `[r2, r1, 1, 0]` | Format D base+index with **scale-enable set**: the AGU supplies the `chwidth`-derived shift. O-7 only fires like this for aligned pointers |
| `fadd r3, r2` | the compressed destructive form, 16 bits, because `rd == rs0` fell out naturally |

There is **no branch on the fall-through path** — the guard branches over the
body and the body falls into the exit. An earlier version emitted an explicit
`bra` to the next instruction, because the target had no branch-analysis hooks
and the generic folder could not act (F-26).

### The same kernel without the alignment attribute

`test/cuda/vadd.cu` is the same source with the alignment attribute removed. Each
pointer then occupies two launch-block slots, and the in-window offset has to be
folded into the index — a fourth addend the three-input AGU cannot take — so
scale-enable stays clear and the index carries bytes rather than elements:

```
_Z4vaddPfPKfS1_i:
	movi r0, 2
	ld.global r1, [r0 + 0]
	srd r2, 0
	srd r3, 1
	mad.lo r1, r3, r1, r2
	ld.global r2, [r0 + 56]
	setp.le p0, r2, r1
	@p0 bra LBB0_2
	shl r1, 2
	ld.global r2, [r0 + 52]
	add r2, r1
	ld.global r3, [r0 + 48]
	ld.global r2, [r3, r2, 0, 0]
	ld.global r3, [r0 + 44]
	add r3, r1
	ld.global r4, [r0 + 40]
	ld.global r3, [r4, r3, 0, 0]
	fadd r3, r2
	ld.global r2, [r0 + 36]
	add r1, r2, r1
	ld.global r0, [r0 + 32]
	st.global r3, [r0, r1, 0, 0]
LBB0_2:
	exit
Lfunc_end0:
```

landed on `rd != rs0` and nothing tries to prevent that (F-29).

### Two instructions, field by field

The O-24 bootstrap, decoded from the real bytes using the §3 bit map:

```
  16-bit instruction at 0x0016: 09 00  ->  DP4_ACC
  raw = 0x0009 = 0000000000001001

  bits         field      value
  --------------------------------------------
  [1:0]        class      0b01  (§2: length from bits [1:0] alone)
  [7:2]        opcode     2
  [7:4]        rd         0
  [11:8]       rs0        0
  [15:12]      rs1        0
```

`ps0 = 4` is `!P0` — bit 2 of a qualifier is the negate bit — and `ps1 = 0` is
`P0`. So this is `por p0, !p0, p0`: all-ones whatever `P0` held, in 16 bits.

And the 48-bit constant:

```
  32-bit instruction at 0x0000: 2c 00 01 00  ->  MOVI
  raw = 0x0001002c = 00000000000000010000000000101100

  bits         field      value
  --------------------------------------------
  [1:0]        class      0b00  (§2: length from bits [1:0] alone)
  [5:2]        fmt tag    0b1011
  [14:11]      rd         0
  [31:15]      imm        2
```

## 6. Disassembly and execution

The simulator drives the *generated* disassembler, so this is the encoding read
back by a different TableGen backend than the one that wrote it. This run has
20 of 32 threads active, so the guard actually diverges. The mask column is the
set of lanes issuing together.

```
  0000  mask=ffffffff  	movi r0, 2
  0004  mask=ffffffff  	ld.global r1, [r0 + 0]
  0008  mask=ffffffff  	srd r2, 0
  000a  mask=ffffffff  	srd r3, 1
  000c  mask=ffffffff  	mad.lo r1, r3, r1, r2
  0010  mask=ffffffff  	ld.global r2, [r0 + 56]
  0014  mask=ffffffff  	setp.le p0, r2, r1
  0018  mask=ffffffff  	@p0 bra 13
  001c  mask=000fffff  	ld.global r2, [r0 + 48]
  0020  mask=000fffff  	ld.global r2, [r2, r1, 1, 0]
  0024  mask=000fffff  	ld.global r3, [r0 + 40]
  0028  mask=000fffff  	ld.global r3, [r3, r1, 1, 0]
  002c  mask=000fffff  	fadd r3, r2
  002e  mask=000fffff  	ld.global r0, [r0 + 32]
  0032  mask=000fffff  	st.global r3, [r0, r1, 1, 0]
  0036  mask=ffffffff  	exit
```

The mask is `ffffffff` through the prologue, narrows to `000fffff` for the body,
and is `ffffffff` again at `exit`. Lanes regroup because their PCs coincide —
there is no bracket instruction and nothing forces it (§1).

## 7. Result

```
  --- CUDA source to executed result ---
  PASS  n=32: 32 lanes correct (16 issue groups)
  PASS  n=20: 32 lanes correct (16 issue groups)
  PASS  n= 1: 32 lanes correct (16 issue groups)
  PASS  n= 0: 32 lanes correct (9 issue groups)
```

`c[i] = a[i] + b[i]` verified as FP32 bit patterns across all 32 lanes at four
divergence levels. Inactive lanes are checked to be *untouched*: `c[]` is
poisoned before each run, so a lane that executed when it should not have would
fail rather than coincidentally agree.

`n=0` is the case where every lane takes the guard and the body is skipped, which
is why its issue-group count is lower.
